## Was / Warum

Ausgangsbasis ist `main` bei `cb844ec1faa35de9a540876c3be195641cef7f4f`.
PR [#12](https://github.com/sl3ndrr/m8e-calc/pull/12) wurde erneut gelesen:
Head `abeb2ee9368e5153f27f716956cd37aa7cc8c8ad`, elf Updates, unverändert.
Der damals neueste CI-Lauf war
[38600369997, Job 115977754810](https://github.com/sl3ndrr/m8e-calc/actions/runs/38600369997/job/115977754810).
`npm ci` scheitert mit `ERESOLVE`, weil jsx-a11y 6.10.2 nur ESLint bis 9
akzeptiert. Tests und Build liefen dort nicht. Der damalige main-CI-Lauf
[38972293002](https://github.com/sl3ndrr/m8e-calc/actions/runs/38972293002) ist erfolgreich.

Die Zielversionen aus #12 sind keine Aussage über den heutigen neuesten Stand.
Die [npm-Metadaten](ap24-package-metadata.json) wurden am 16.10.2026 über
`npm view` auf einem GitHub-Runner mit Node 24.21.0/npm 11.19.0 neu erhoben.
Keine deklarierte Engine bedeutet keinen universellen Kompatibilitätsnachweis.
Die Version in „main“ stammt aus dem Lockfile, nicht nur aus dem Manifestbereich.

## Dependabot-Regeln

Wöchentlicher Lauf, bis zu 15 offene npm-Version-PRs. Die spezifischen Gruppen
stehen vor den Auffanggruppen, weil Dependabot den ersten Treffer verwendet:

| Gruppe               | Inhalt / Grenze                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `eslint-major`       | Ausschließlich das gekoppelte Paar `eslint` / `@eslint/js`; Major, eigener Migrations-PR. Keine anderen Majors darin.                                  |
| `lint-toolchain`     | ESLint, Plugins, typescript-eslint und Globals; Patch/Minor.                                                                                           |
| `test-toolchain`     | Testing Library, Vitest, jsdom, Playwright, axe, fast-check; Patch/Minor.                                                                              |
| `build-toolchain`    | Übrige Dev-Pakete wie Vite, TypeScript, Node-Typen, Prettier; Patch/Minor. React-Typen ausgeschlossen.                                                 |
| `react-stack`        | React/DOM samt Typen, React Aria und Zustand; Patch/Minor.                                                                                             |
| `codemirror`         | CodeMirror und Lezer gemeinsam; Patch/Minor.                                                                                                           |
| `local-font-sources` | Roboto-Fontquellen; Patch/Minor. Font-Regeneration bleibt ein eigener Review-Schritt.                                                                  |
| `runtime`            | Übrige Runtime-Pakete; Patch/Minor. Motion, KaTeX, Material-Farben und Symbolfonts sind ausgeschlossen und erhalten einzelne PRs, auch bei 0.x-Minors. |
| `github-actions`     | Actions-Patch/Minor; Actions-Majors einzeln.                                                                                                           |

Andere npm-Majors bleiben einzelne PRs. Insbesondere werden Node-Typen 26,
Vitest 5 und jsdom 30 nicht mit ESLint 10 gebündelt. Es gibt keine `ignore`-
Regeln, kein globales Major-Verbot, keinen abweichenden Zielbranch und keine
Security-Sammelgruppe: Security-Updates behalten die individuellen Dependabot-PRs.
Ein offener Migrations-PR ist ein Reviewauftrag, keine Freigabe zur Installation.
Grundlage: [offizielle Optionsreferenz][dependabot].

## Test / Reproduktion

Node 24 LTS aus `.nvmrc`, in der Erzeugung konkret Node 24.21.0 mit dessen npm
11.19.0. Da der Arbeitscontainer Git/npm-Netzwerkzugriff verweigert, erfolgen
Installation und Ausführung nachvollziehbar auf GitHub Actions. Keine lokalen
Prüfungen behaupten, die dort nicht ausgeführt wurden.

```sh
node --version
npm --version
npm install --package-lock-only
npm ci
npm ls --all
npm run check
npx playwright install --with-deps chromium firefox webkit
npx playwright test --project=chromium --project=chromium-graph-performance
npm run build:gallery
npm run test:e2e:gallery
npx playwright test --project=firefox --project=webkit --project=qa-performance
npx playwright test --project=qa-visual
npm audit --json
```

Lockfile regulär erzeugen; keine manuellen Versions-/Integrity-Einträge, keine
`--force`-/`--legacy-peer-deps`-Flags, keine Overrides. Der zeitweilige
Erzeugungsworkflow arbeitet mit `contents: read`, veröffentlicht keinen Code und
wird vor Abschluss aus dem PR-Diff entfernt. Anschließend müssen die normalen
CI-/QA-Workflows mit dem eingecheckten Lockfile selbst erfolgreich laufen.

Gezielte Runtime-Abdeckung: `scientific.spec.ts` bedient den echten CodeMirror
(Definitionen, Integral, Bruch, komplexe Werte), prüft sichtbares KaTeX und axe.
`graph.spec.ts` prüft Canvas/Worker, wiederholtes animiertes Fit, Pan/Zoom,
Parameter und reduzierte Bewegung. `controls-polish.spec.ts` prüft echte
Zwischenzustände von Animationen im Galerie-Build. Die Hardening-Tests prüfen
Tastatur/Fokus mit React Aria, CSP, Offline/PWA und lokale Auslieferung.
`qa-visual` vergleicht die 24 eingecheckten Referenzen; keine Baselines ersetzen.
Die bestehenden Roboto-/Symbol-WOFF2-Dateien und Fontlizenzen bleiben unverändert.
KaTeX-CSS und -Fonts kommen weiterhin aus dem lokalen Vite-Bundle und in den
PWA-Precache; keine CDN-Quelle hinzufügen.

Erfolgreiche Installation allein ist kein Security-Nachweis. `npm audit` erfasst
nur zum Abfragezeitpunkt bekannte Registry-Advisories und deren Lockfile-Matching,
nicht unbekannte Lücken, die Vertrauenswürdigkeit eines Publishers oder die
Sicherheit jedes Laufzeitpfads. Auch transitive und Dev-Abhängigkeiten auswerten;
bei neuen Befunden betroffenen Pfad, Advisory und Fix separat untersuchen.

Die abgeschlossenen Läufe und Audit-Ergebnisse werden im Wartungs-PR verlinkt.
Ein vorbereiteter oder noch laufender Workflow gilt nicht als bestanden.

## Offen / Folge-Issues

Tracking: [#31](https://github.com/sl3ndrr/m8e-calc/issues/31) für ESLint,
[#32](https://github.com/sl3ndrr/m8e-calc/issues/32) für die weiteren getrennten Migrationen.

- **F1 · ESLint 10:** Upstream-Peerfreigabe von jsx-a11y abwarten bzw. separat
  mit vollständiger Accessibility-Regelparität evaluieren. Dann ESLint und
  `@eslint/js` gemeinsam, Plugin-/Rule-API und Recommended-Diff prüfen; frisches
  `npm ci`, vollständiges Lint und `check` ohne Resolver-Umgehung. Solange
  jsx-a11y 6.10.2 aktuell ist, bleibt ESLint 9 die kompatible Linie.
- **F2 · Motion 14:** `motion/react`-/Vanilla-Aufrufstellen, Emotion-Filtering
  und interne Paketauflösung prüfen; Rechnerziffern, Keypad, Dialog-/Menü-Exit,
  Graph-Fit/Unterbrechung sowie Full/Reduced/Off mit echten Zwischenbildern
  abnehmen. Keine pauschale Snapshotfreigabe. Ziel neu aus Metadaten bestimmen.
- **F3 · jsdom 30:** Node-Mindestversion ausdrücklich entscheiden; dann
  ResourceLoader-/CSSOM-/Focus-/Pointer-/CodeMirror-/React-Aria-Verhalten gegen
  die reale Browserabdeckung vergleichen. Aktuell 30.1.3 statt des inzwischen
  überholten 30.1.2 prüfen. Nicht zusammen mit Vitest 5 migrieren.
- **F4 · Vitest 5:** UI-/Engine-Projektisolation, vererbte Vite-Plugins,
  `clearMocks`, Mock-Hoisting, asynchrone Assertions und Matcher-Semantik einzeln
  prüfen. Bestehende Tests inhaltlich erhalten; keine Abschwächung von Assertions.
  Patch 4.1.12 wird unabhängig davon bereits in AP24 mitgenommen.
- **F5 · Node-Typen 26:** Nur zusammen mit einer ausdrücklich beschlossenen
  Node-Runtime-Migration; `.nvmrc`, Engine und CI gemeinsam anpassen. Unter Node
  24 bleibt die jeweils aktuelle 24er-Typenlinie maßgeblich.
- **F6 · Material Color Utilities 0.4:** Den endungslosen Import von
  `dynamiccolor/dynamic_color` in `color_spec_2025.js` upstream beheben lassen.
  Nach korrigierter Veröffentlichung nativen Node-Import, Vitest-Konfigurationsstart,
  Farb-API, bestehende Farb-Snapshots, volle Kontrastmatrix und Browserbilder prüfen.
  Beleg: [fehlgeschlagener vollständiger Lauf](https://github.com/sl3ndrr/m8e-calc/actions/runs/38973333923/job/117216710354).
  Der frühere isolierte Diagnose-Schritt hat den Startfehler geloggt, aber mit
  nachfolgend erfolgreichem Typecheck als letztem Befehl keinen verlässlichen
  Gesamtstatus geliefert. Maßgeblich ist der gescheiterte vollständige `check`.
- **Font-Regeneration:** Material Symbols 0.48.0 liefert neue Eingabefonts für
  das Subsetting. Vor einer Regeneration alle verwendeten Ligaturen, FILL,
  Gewichte/optische Größe, Checkbox-/Theme-Symbole und lokale Offline-Fonts
  visuell abnehmen. AP24 ändert die ausgelieferten Subsets nicht.
- **PR #12:** Nach Integration der Ersatzlösung
  [#30](https://github.com/sl3ndrr/m8e-calc/pull/30) am 16.10.2026 geschlossen.
  Die zurückgestellten Einzelmigrationen bleiben über #31/#32 und
  [AP33](AP33.md) mit #50 verfolgt. Kein automatischer Merge, Release oder Tag.
