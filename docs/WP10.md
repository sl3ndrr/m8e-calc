# WP-10 · Resetumfang und Orientierung im Einstellungsdialog

Auditbezug D3. Umsetzung und commitgebundene Testergebnisse:
[PR #89](https://github.com/sl3ndrr/m8e-calc/pull/89).

## Resetvertrag

Aktion, Bestätigung und Erfolgsmeldung nennen in de/en Einstellungen und Verlauf.
Der Reset umfasst globale Einstellungen einschließlich Kurszustimmung,
den globalen Verlauf aller Modi samt Pins, Sichtbarkeit und Limit,
den letzten Modus sowie den Themecache. Die normale Themeanwendung kann den
Cache anschließend neu erzeugen; die App wechselt zu Einfach.

Wissenschaftliches Environment, Umrechnerfavoriten, Paare und Zahlenformatierung,
Kurscache samt Abrufzeit und Offline-Dateien bleiben erhalten.
Abbrechen verändert diese Daten nicht. Neue Speicherarten benötigen einen
ausdrücklichen Resetvertrag; die Aktion verspricht keine vollständige
Datenlöschung.

## Dialog und Fokus

Die optionale Dialogeinstellung `scrollable` trennt den festen Kopf mit Titel
und Schließen von der eigenen Scrollfläche. Der Kopf belegt Layoutplatz;
Innenabstand, Scrollreserve und Scrollmargen berücksichtigen Fokusringe.
Benannte Abschnitte und Allgemein/Währung gliedern die Einstellungen.
Abbrechen und Bestätigen der Inlinebestätigung führen den Fokus zur Resetaktion
zurück. Eigene fokussierte Controls werden im nächsten Frame sichtbar
ausgerichtet; Fokuswechsel, Portalziele und Exit-Inhalte werden berücksichtigt.

Suchbare `Select`-Controls fassen Input und Button in React Arias `Group`
zusammen. Der Group-Ref vermeidet den Legacy-Pfad, der während einer
ResizeObserver-Lieferung synchron nachmisst und den Menüzustand aktualisiert.
Der globale Fehlerhandler und die Toast-FIFO behalten ihren Vertrag.

## Regressionen

`SettingsDialog.test.tsx` und `e2e/settings-reset.spec.ts` prüfen Resetumfang,
Abbrechen, Persistenz, Offline-Cacheerhalt, de/en und die Tastaturführung.
Drei-Engine-Reflow bei 200 % und echter Chromium-Tabzoom bei 100/200 %
sind getrennte Prüfungen. Die Währungsregression deckt Laden, API-Fehler und
Offline-Fallback ab. Reguläre CI prüft zusätzlich Visuals, Galerie,
Build-Provenienz, Performance und Paket-Audit.

```sh
npm ci
npm run check
npm run test:e2e -- --project=chromium --project=firefox --project=webkit e2e/settings-reset.spec.ts
npm run test:e2e -- --project=chromium e2e/settings-native-zoom.spec.ts
npm run test:e2e -- --project=webkit e2e/currency.spec.ts:235 --repeat-each=30 --workers=2 --retries=0
npm run test:e2e -- --project=webkit e2e/currency.spec.ts --repeat-each=10 --workers=2 --retries=0
npm run build:gallery
npm run test:e2e:gallery -- --project=gallery e2e/components.spec.ts e2e/accent-picker.spec.ts
```

`check` erzeugt den normalen Produktionsbuild. Der Galerie-Build verwendet
sein eigenes Ziel `dist-gallery/`.
