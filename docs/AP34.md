Stand: 19.10.2026. Ausgangsbasis ist main
`5255dec204ca6a845c5aa0b30ba52eebeb60e975`, Branch
`feat/ap34-jsdom30`, [PR #59](https://github.com/sl3ndrr/m8e-calc/pull/59).
[AP33](AP33.md) / #49 ist integriert und entscheidet ausdrücklich für

es ist kein zusätzliches Produktfeature und keine Voraussetzung für AP39.
Die dortigen Live-/Releaseentscheidungen bleiben separat.

**jsdom 27.4.0 → 30.1.3**, Manifest `^30.1.3`, reguläres Lockfile.
Die [offizielle Veröffentlichung 30.1.3][patch] und die am 19.10. frisch
abgefragte npm-Registry bestätigen den höchsten stabilen 30er-Patch,
ohne Deprecation. Er repariert insbesondere die in 30.1.2 eingeführten
Fokus-/Interaktionsverlangsamungen und weitere CSSOM-Fehler.
Das ist die konkrete Ablösung des Angebots 27.4.0 → 30.1.2 aus
[Dependabot #36](https://github.com/sl3ndrr/m8e-calc/pull/36).

#36 ist offen und nicht integriert: Head
`47ee19c6833bf34666c950a7c7f9f0c28b9a2c15`, bei Erhebung nicht mergefähig.
Seine aktuellen historischen Checks `check`, `browsers`, `visual`,
`measure (before/after)` und `images` sind erfolgreich, bedingte
Paketjobs übersprungen. Das sind keine Nachweise für diesen PR oder die
heutige orchestrierte CI. **#36 erst nach Integration von #59 als ersetzt
schließen**; #32 und die Roadmap bleiben bis dahin unerledigt.

Keine Migration auf jsdom 31, Vitest 5, Motion 14 oder Node 26.
`@types/node` bleibt auf **24.19.2 / ^24.19.2**. Produktabhängigkeiten,
Produktcode und visuelle Referenzen sind unverändert.

## Node-/npm-Vertrag

Neu unterstützt: **Node `>=24.15.0 <25`**. Das ist die ausdrücklich
beauftragte Anhebung innerhalb Node 24; ältere 24er-Versionen sind nicht
mehr unterstützt. `.nvmrc` bleibt `24` und verfolgt die gepflegte Linie.
Manifest, [Entwickleranleitung](../README.md), [AGENTS](../AGENTS.md) und
CI bilden denselben Bereich ab.

Die [frischen Metadaten](ap34-package-metadata.json) enthalten die
Engines aller tatsächlich aufgelösten Lockfile-Pakete sowie offizielle
Registry-Engines und Peers der verwendeten Einstiegspakete:

| Tatsächlich verwendet | Relevanter Vertrag innerhalb Node 24 |
| --- | --- |
| jsdom 30.1.3 | mindestens 24.15.0; optionaler Peer `canvas ^3.2.3` |
| @asamuzakjp/css-color 7.1.7, dom-selector 10.0.4, w3c-xmlserializer 6.0.0 | ebenfalls mindestens 24.15.0 |
| undici 8.12.2 | `>=22.19.0`, damit jede 24er-Version |
| Vite 8.3.4 / plugin-react 6.1.2 | `^20.19.0 || >=22.12.0`, keine höhere 24er-Untergrenze |
| Vitest 4.1.12 | `^20.0.0 || ^22.0.0 || >=24.0.0`; jsdom `*`, Vite 6/7/8 |
| React Aria Components 1.22.1 / CodeMirror View 6.43.14 | keine höhere Node-Engine; React-Aria-Peers erlauben das verwendete React 19 |

Die Schnittmenge innerhalb der bewusst gewählten 24er-Linie beginnt daher
bei **24.15.0**. Ein semver-Abgleich aller erfassten Engines akzeptiert
24.15.0 und 24.22.0; 24.14.0 wird durch die genannten vier jsdom-Pakete
abgelehnt. Fehlende Engines sind keine universelle Kompatibilitätszusage.
Canvas ist optional und nicht installiert; es wird für diese Migration
nicht hinzugefügt. `npm ci --engine-strict` und die echten Läufe prüfen
den tatsächlich installierten Baum zusätzlich.

Lockfile-Erzeugung: **Node 24.22.0, npm 11.19.0**,
`npm install --package-lock-only` auf dem vorhandenen Lockfile nach
gezielter Manifeständerung. Kein allgemeines `npm update`, keine Overrides,
kein `--legacy-peer-deps` und keine manuellen Integrity-Eingriffe.
Alle veränderten Paketknoten gehören zur jsdom-Dev-Kette; die
Produktabhängigkeiten behalten dieselben Lockfile-Einträge.
npm 11.19.0 ist für Erzeugung und die beiden Check-Umgebungen festgehalten;
die aktuelle Node-24-Veröffentlichung war bei Erhebung **24.22.0**
(bündelt npm 11.19.1). Ein Wechsel auf npm 12 ist nicht Teil dieses Pakets.

Die vorhandene Vitest-4-jsdom-Umgebung wird nativ gestartet; kein Netzwerk-/Loader-Mock hinzugefügt. |

Reale CodeMirror-Styles, React-Aria-Sichtbarkeit, axe-Komponenten und bestehende Farb-/Theme-Tests bleiben in der vollständigen UI-Auswahl. Keine CSS-/Snapshotkorrektur ohne Produktbefund. |
| [jsdom 30][v30] und [30.1.3][patch]: Fokus / CSS | Erhöhte Engine-Untergrenze, CSS-Unterstützung und berechnete Werte; 30.1-Patches reparieren Fokus nach Entfernung/Deaktivierung sowie CSS-Invalidierung. Dialog-/Popover-/Menü-Escape, Fokusrückgabe, AccentPicker-Iris, Radio-/Toolbar-Navigation werden durch bestehende Tests geprüft. Keine Unterdrückung von blur/focus oder globale Fokuskorrektur. |
| Pointer-/Mausereignisse und React Aria | Bestehende user-event-Klicks, native Checkboxaktivierung, deaktivierte Controls, Enter/Space, Menüs und Segmentsteuerung bleiben unverändert. Keine Ersetzung von PointerEvent durch MouseEvent und kein zusätzliches globales Event-Mocking. Echte Chromium-/Firefox-/WebKit-Pfade bleiben Referenz. |
| CodeMirror | `ExpressionEditor.test.tsx` verwendet den echten Adapter: Einfügen, Diagnosemarkierung, sichtbare Completion vor Escape/Enter. Die bereits vorhandenen Range-Geometrieadapter in `src/test/setup.ts` bleiben auf jsdoms fehlendes Layout begrenzt; ResizeObserver, matchMedia und scrollIntoView werden nicht erweitert. Browser-Editor/Completion und Rechnerintegration prüfen die echte Geometrie. |

Vite-Konfiguration und UI-Testsetup müssen für diese Migration nicht geändert
werden. `npm test` führt die **vollständigen Projekte getrennt** aus:
`npm run test:ui`, danach `npm run test:engine`. Die vorhandenen
Include-/Exclude-Mengen und sämtliche Testdateien, Assertions, Zeitgrenzen
und Skips bleiben unverändert. Domänentests behalten das Node-Projekt ohne
UI-Setup. Die bereits vorhandenen Canvas-`getContext`-Hinweise ohne optionalen
Canvas-Peer werden nicht durch zusätzliche globale Mocks versteckt.

## Grenzen / Offen

Lokal sind GitHub-Git-Clone und npm-Registry mit HTTP 403 gesperrt.
Daher kein lokales `npm ci` oder `check` behauptet; die konkreten
GitHub-Runner-Läufe sind maßgeblich. Lokal wurden die unverändert
übertragenen generierten Lockfile-Daten und die Engine-Schnittmenge geprüft.
Der temporäre Diagnoseworkflow wird aus dem finalen Diff entfernt.

Finale Checks auf dem tatsächlich letzten PR-Commit stehen bis zum Abschluss
der Läufe offen. Integration, #36-Schließung und Erledigt-Markierung in
Roadmap/#32 bleiben dem späteren Merge vorbehalten. Kein automatischer
Merge, Release, Tag oder Deployment; AP39 und die übrigen AP24-Folgepakete
bleiben eigenständig.
