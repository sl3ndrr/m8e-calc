## Befund und Korrektur

Der ursprüngliche Importhandler verwendet nach `await file.text()` weiterhin
`settings.onlineRates` aus dem Start-Render. `importSettings` validiert streng
und liefert bereits korrekt `onlineRates: false`; der Fehler liegt im
anschließenden Zurückschreiben der alten Zustimmung.

Die native Node-Probe führt den Originalhandler und den neuen Handler mit
echtem kontrolliertem `File.text()`-Promise sowie den tatsächlichen
Store-Initializerfunktionen aus. Ihr kleiner Set-/Persistenzadapter ist
ausdrücklich **kein Zustand-Store und kein Browser**.

| Zustimmung beim Start | Während des Lesens gewählt | Original nach Abschluss          | Korrektur im Modell |
| --------------------- | -------------------------- | -------------------------------- | ------------------- |
| true                  | false                      | true: Widerruf überschrieben     | false               |
| false                 | true                       | false: Aktivierung überschrieben | true                |
| true                  | true                       | true                             | true                |
| false                 | false                      | false                            | false               |

Die Datei enthält in den Gegenproben jeweils sowohl true als auch false.
Zusätzlich ist die umgekehrte Abschlussfolge geprüft: erst Importabschluss,
dann Widerruf. Ergebnis: **18 erfolgreiche Original-/Korrektur-Gegenproben und
drei erfolgreiche Fehlergegenproben**, keine Sleeps.
[Reproduzierbare Probe](wp03-source-probe.mjs),
[Rohresultate / Quellhashes](wp03-source-evidence.json).
Das bestätigt den Zustandsfehler, keinen tatsächlich ausgelösten unerlaubten
Request. Die bestehenden Cache-/Vierstundenregeln können Requests zusätzlich
verhindern; aus einer reaktivierten Zustimmung folgt kein gemessener Request.

`applyImportedSettings` liest `state.onlineRates` innerhalb desselben
funktionalen `set`, das alle übrigen validierten Einstellungen übernimmt.
Ein Start-Snapshot darf die Aktion halten; er liefert keinen Zustimmungswert.
Die Aktion akzeptiert typisiert die Einstellungen ohne Zustimmungsfeld und
überschreibt dieses Feld auch bei einem strukturell kompatiblen vollständigen
Settingsobjekt stets mit der aktuellen Storezustimmung.

Strenge Dateivalidierung, 100000-Byte-Grenze und bestehende de/en-Fehlermeldung
bleiben erhalten. FileTransfer, Migrationen, Reset-/Restore-/Snackbaraktionen,
Kursclient, Providerendpoint, zugelassene Requestdaten und Cacheformat sind
unverändert. Abbruch und Verwerfen verspäteter Antworten bleiben wirksam;
Dependencies, Lockfile, Domänen, Lazy-Grenzen, Tokens, numerische Grenzen,
Budgets, Fristen, Retries und Bildbaselines sind unverändert.
