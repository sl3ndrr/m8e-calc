# AP23 · Internes Designlab

Basis ist `main` **940d147ed3ec103887775c18e99f4155a84bab38** vom
16.10.2026. AP18 (#25) und AP20 (#27) sind darin bereits integriert.

Die Anwender-App enthält vier Rechnermodi und Einstellungen. Das Designlab ist
ein internes Entwicklungs- und Prüfwerkzeug, kein aktivierbares Anwenderfeature.

| Ziel              | Befehl                  | Ausgabe / Preview                          | Lab                                              |
| ----------------- | ----------------------- | ------------------------------------------ | ------------------------------------------------ |
| Entwicklung       | `npm run dev`           | Vite-Devserver                             | `#/design` verfügbar                             |
| Produktion        | `npm run build`         | `dist/`, `npm run preview`                 | kein Link, kein Import; `#/design` zeigt Einfach |
| Galerie-Testbuild | `npm run build:gallery` | `dist-gallery/`, `npm run preview:gallery` | explizit mit Vite-Modus `gallery`                |

`__INTERNAL_DESIGN_LAB__` wird ausschließlich beim Bauen ersetzt. Kein URL-Parameter,
Storage-Wert, Einstellungsimport oder öffentliches Menü kann diese Grenze ändern.
`App.tsx` hält den dynamischen Import im bedingten Zweig. `DesignLab.tsx` importiert
sein CSS selbst; die Komponentenmatrix, MotionDemo und labexklusive de/en-Texte
liegen hinter derselben Grenze. Gemeinsam verwendete UI-Komponenten und deren
Abhängigkeiten bleiben für Rechner und Einstellungen verfügbar. Die Bibliothek
und sämtliche vorhandenen Tests bleiben erhalten. Der bisher eager eingebundene
ShortcutDialog lädt jetzt wie Settings/Palette erst beim Öffnen, um das bestehende
Startpfad-Gate auch mit dem geänderten Chunkgraph einzuhalten; die globalen Kürzel
und der Dialogvertrag bleiben gleich. Der Fehler-Reload frischt auch den neuen
ShortcutDialog-Chunk auf, bevor er die App neu lädt. Ungenutzte Fundament-Platzhaltertexte sind
entfernt. Gemeinsam benötigtes Rail-Schriftgewicht und Hover bleiben ausdrücklich
in der öffentlichen NavigationRail statt implizit in Lab-CSS. Die noch gemeinsam
verwendete `.icon-button`-Klasse (Schließen-Knopf der Akzentwahl und Motion-Demo)
bleibt in `base.css`.

Der Buildadapter verweigert einen normalen Build mit gerenderten Labmodulen und
einen Galerie-Build ohne DesignLab. `test-results/ap23/modules-*.json` dokumentiert
Chunkimporte und tatsächlich gerenderte Module einschließlich Abhängigkeiten.
`build-target.json` markiert das Ziel; `scripts/check-build-target.mjs` prüft
Marker, Manifest, exklusive CSS-/Textproben und Service-Worker-Precache. Alle vier
Modus-Chunks müssen weiterhin im Precache liegen. Es gibt keine nachträgliche
Precache-Ausnahme, die versehentlich ausgelieferte Labchunks verdecken würde.

## Reproduktion

```sh
npm ci
npm run check
node scripts/qa-bundle.mjs
npm run build:gallery
npx playwright install --with-deps chromium
npx playwright test --project=chromium --project=chromium-graph-performance
npm run test:e2e:gallery
GALLERY_DEV=1 npm run test:e2e:gallery -- --grep 'gallery contains every'
# Galerieaufnahmen mit separatem Preview in einem zweiten Terminal:
npm run preview:gallery -- --host 127.0.0.1 --port 4174 --strictPort
npm run screenshots:gallery
```

`playwright.config.ts` prüft ausschließlich den normalen Build: App, PWA/offline,
Lazy-Modi, normale Pfade, Theme-/Akzentwahl im App-Kontext und Screenshotregression.
`playwright.gallery.config.ts` führt Komponenten-, Lab-Theming-, Controls- und
native Zoomtests gegen Port 4174 aus. `GALLERY_DEV=1` wählt ausschließlich für
diesen Testserver den Vite-Devserver; der vollständige Komponenten-/axe-Smoke
prüft auch diesen Entwicklungsbetrieb. Bestehende Theming-Prüfungen mit der
Lab-Motionmatrix behalten ihr Ziel; normale Shell-/Hardeningprüfungen bleiben
am Produkt. Releasebilder und Lighthouse verwenden weiterhin `dist/`.

CI baut und prüft beide Ziele; Pages baut ausschließlich das normale Ziel und
prüft es unmittelbar vor dem unverändert auf `dist` begrenzten Upload erneut.
Galerie-Builds schreiben niemals nach `dist/`. Der AP23-Nachweis prüft zusätzlich
Hashgleichheit von normalem HTML und SW vor/nach dem Galeriebau.
