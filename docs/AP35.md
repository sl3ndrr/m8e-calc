| Bereich | Befund und konkrete Änderung |
| --- | --- |
| Inline-Projektvererbung | Vitest 5 setzt `extends` standardmäßig auf true. Beide vorhandenen Inline-Projekte erhalten ausdrücklich **`extends: false`**, entsprechend ihrem bisherigen Vitest-4-Verhalten. Keine pauschale Übernahme eines fremden Konfigurationsbeispiels. |

| Define / Environment | Der vorhandene projektlokale Define `__INTERNAL_DESIGN_LAB__: 'true'` bleibt in beiden Projekten. UI bleibt jsdom mit ausschließlich `src/test/setup.ts`; Engine/Units/Graph bleiben Node ohne UI-Setup. Include-/Exclude-Mengen sind unverändert. `pool: threads` und maximal zwei Worker bleiben. |
| Mock-Lebenszyklus | Vitest 5 aktiviert `clearMocks` standardmäßig. | Weitere entfernte APIs | Kein `test.sequential`, alter top-level `bench`, Vitest-Benchmarkkonfiguration, eigener Pool/Reporter oder Coverage-Adapter im Produktsetup. Engine-/Graph-/2D-Benchmarks sind bestehende Node-Skripte und bleiben unverändert. |
